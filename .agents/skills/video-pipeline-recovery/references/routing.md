# Failure ownership routing

| Failure evidence | Owning stage |
|---|---|
| direction, runtime policy, frame, subject definition, global clause | 01 Premise |
| structured sheet prompt, identity board, panel or sheet image | 02 Sheets |
| dramatic progression, scene event, incident density, invented story asset | 03 Scenario |
| scene intention translation, blocking, shot coverage, composition, camera, performance, shot time | 04 Shot design |
| missing reference/manual, global reference preflight, start plate | 05 Plates |
| approved-plate observation or base C01 scenario/camera/technique/time translation | 05.5 Motion prompt |
| generated-video action execution, motion continuity, C02–C10 retry prompt or take | 06 Motion |
| trim, retime, ordering, transition, sound or master render | 07 Edit |
| audit evidence, defect disposition, release eligibility | 08 Review |

Route to the earliest stage that owns the wrong fact. A later stage may not silently redefine an upstream fact. Preserve downstream media as historical evidence even when it becomes stale.

Examples:

- Landscape contract plus `Vertical production plate` in a plate prompt: repair the Stage 05 prompt if Stage 01 is correct; repair Stage 01 only if the frame contract itself is wrong.
- Unrelated `tool bag` leakage in an automobile sheet: repair Stage 02. A tool bag intentionally introduced as a later story prop becomes Stage 03 reference debt and Stage 05 reference work instead.
- Two visible people labeled `single`: repair Stage 04 composition and regenerate dependent Stage 05–07 assets.
- A missing `NEW-*` prop reference: keep the scenario, fulfill the debt in Stage 05, and regenerate dependent plates.
- A usable approved plate whose starting pose needs a different opening action or camera path: keep the plate and repair Stage 05.5. Do not duplicate Stage 05 image generation.
- A C01 prompt that ignores visible hand occupancy or camera affordance in the approved plate: repair Stage 05.5. A C01 video that receives the correct prompt but executes it poorly belongs to Stage 06.
- A slow-motion shot that cannot fit a naive real-time event length: repair Stage 04 time domains or Stage 07 execution, not Stage 03 by mechanically shortening the event.
