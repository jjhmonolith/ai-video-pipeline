# 프로젝트 개요

> 역사 문서: 아래 내용은 재구축 직전 v2 상태를 설명한다. 현행 정본은

> 특히 아래의 결정론적 production compiler는 v3 창작 정본이 아니다.

> 기준일: 2026-08-27  
> 상태: 3단계 scene design v3, 4단계 LLM directorial plan + production compiler v2, 5–6단계 순차 생성 하네스 구현

## 목적

아이디어마다 새 스크립트를 쓰는 방식이 아니라, 한 attempt의 계약이 조사·생성·편집·검수를 끝까지 구속하는 반복 가능한 영상 제작 시스템을 만든다.

핵심은 생성 호출 수가 아니라 다음 네 가지다.

- 같은 입력과 계약에서 무엇이 만들어졌는지 추적할 수 있다.
- 후보·폐기본·채택본이 섞이지 않는다.
- 자동 검사는 사람이 판단할 대상을 좁히고, 사람의 승인을 대신하지 않는다.
- 앞 단계가 바뀌었을 때 다시 만들어야 할 하류 산출물을 찾을 수 있다.

## 아키텍처

```text
사람의 지시
  -> attempt 계약
  -> 조사와 요소 정의
  -> 레퍼런스 시트
  -> 시퀀스·신·사건 설계
  -> LLM 연출 treatment·setup·shot·시간 설계
  -> 결정론적 production compile
  -> 컷 이미지
  -> 모션
  -> 편집
  -> 자동 QA + human gate
  -> 승인된 결과물
```

계약은 `<attempt>/01-premise/output/contract.json`에 있고 단계 이름, 총 편집 길이의
`runtime_contract`, 생성 프레임, 납품 프레임, 이미지 역할, 시트 종류, 금지 조항,
요소, 조사 상한, 시나리오 구조를 정한다. 45초나 60초는 파이프라인 고정값이 아니다.
각 도구는 값을 재기입하지 않고 계약을 로드한다. 영수증은 계약 digest를 기록해
산출물이 어떤 조건에서 만들어졌는지 남긴다. 로컬 H3 생성은 가로 `1344×768` 또는
세로 `768×1344`, `24fps`로 제한되며 플랫폼용 최종 해상도는 `delivery_frame`에서
별도로 선언한다.

## 현재 검증 범위

`runs/sky-village-plumber/attempts/v1-pilot`에서 다음을 확인했다.

- 주제가 실사 자동차에서 어린이용 애니메이션으로 바뀌어도 같은 1~3단계 모듈이 동작한다.
- 계약의 요소 선언에서 조사 질문과 정의가 만들어진다.
- 요소별 정의가 종류에 맞는 시트로 변환된다.
- 기존 시나리오는 호환 감사하고, 신규 시나리오는 sequence→scene→event와 reference debt를 만든다.

시트 생성 뒤 계약이 확장되어 2단계 영수증의 전체 digest는 현재 계약과 다르다. 정의·프롬프트·적용 조항·이미지 계획·결과 크기를 다시 대조했고 사용자가 4장을 현행 최신 산출물로 확인했다. 원래 영수증은 보존하고 `02-sheet/qa/contract-compatibility.json`에 단계 한정 호환 판정을 남겼다.

아직 실제 이미지 production으로 검증하지 않은 핵심은 관련 reference가 `05-plate`의
시작 이미지에 물려 정체성과 공간 관계를 유지하는지, first-only 조건이 `06-motion`에서
의도한 동작을 만드는지, `08-review`가 자동 검사와 사람 판단을 올바르게 결합하는지다.
5단계 runner는 3–4단계에서 새로 생긴 reference debt와 interaction manual의 5A 선행
승인, 전역 레퍼런스 장벽, 5B 시작판의 한 장씩 AI 검증하는 최대 10회 변주 하네스,
모드별 선발, 영수증과 H3 handoff를 담당한다. 6단계도 best-of-N을 폐기하고 C01 한
take부터 시작해 실패할 때만 C10까지 하나씩 추가한다.
