# 4단계 H3 전용 동작 설계 · 고정 입력 비교 실험

> 작성: 2026-08-26  
> 상태: 4단계 구현, 5단계 카나리아 이미지 비교, H3 영상 14개 생성 및 사람·AI 블라인드 평가 완료

## 결론

4단계는 영상을 만드는 단계가 아니다. 고정된 1단계 브리프·요소 정의, 2단계 시트, 3단계 시나리오를 받아 `한 샷에서 무엇만 변하고 무엇은 절대 변하지 않아야 하는지`를 H3가 실행 가능한 계약으로 컴파일한다.

영상 엔진은 MiniMax H3 하나로 고정한다. `i2v`, `fl2va`, `guided_fl2va`는 모델 선택이 아니라 H3에 첫 프레임·끝 프레임·서로 다른 중간 상태를 어떻게 조건으로 넣을지 정하는 경로다. 화면 좌표 궤적은 H3의 직접 입력이라고 주장하지 않는다. 피사체 track과 tolerance는 5단계 판 제작의 주석 계약이자 6단계 결과의 QA 기준이다.

실험에서는 M4 `H3 adaptive`가 가장 완전한 구조였지만, 어느 방식도 5단계 단일 생성본 그대로는 합격하지 못했다. 공통 실패는 다음과 같다.

- 시작판이 행동 직전이 아니라 이미 밸브를 잡거나 손짓하는 진행 상태였다.
- 끝판에서 요구 동작뿐 아니라 카메라·배경·물체 형상·인물 크기가 함께 바뀌었다.
- 한 문장에 여러 행동이 들어 있으나 3단계에 `sub_beats`가 없으면 안전하게 자동 분해할 수 없었다.
- 좋은 시작판과 좋은 끝판을 독립 선발하는 방식은 서로 맞지 않는 두 이미지를 만들 수 있다.

따라서 M4를 조건부 기본안으로 삼되, H3보다 앞에 `원자 동작 확인 → 시작판 선발 → 같은 시작판의 끝판 편집 후보 생성 → 이미지 쌍 공동 선발`을 강제한다. 실패한 이미지 쌍은 긴 영상 프롬프트로 보상하지 않고 5단계에서 다시 만든다.

## 4단계의 입출력

### 입력

- 1단계: 방향 원문, 계약, 관련 요소 정의, 금지 조항
- 2단계: 요소별 시트와 승인·준비 상태
- 3단계: 비트 순서, 사건, 총 길이, 인물·사물·장소 ID, 가능하면 명시적 `sub_beats`
- 운영 상태: 이전 단계 해시, 사람 승인 상태, 과거 산출물의 호환 경고

과거 배관공·펜트하우스 v1의 규격·게이트 실패는 이번 비교 실험 안에서만 비차단으로 기록했다. 정식 산출물 승격 규칙을 완화한 것은 아니다.

### 역할

1. 전체 길이와 사건을 바꾸지 않고 narrative beat를 촬영 가능한 shot으로 나눈다.
2. 한 shot에 주 행동 하나와 주 변화 하나만 배치한다.
3. 카메라를 `movement / speed / framing / end / angle`로 완결한다.
4. 정확한 피사체 이동·접촉·회전은 카메라를 `locked`로 두고, 카메라 움직임은 H3 자연어 지시로만 분리한다.
5. 시작·끝 상태, 불변 요소, 허용 변화, 동작 방향, 변화량 예산을 명시한다.
6. H3 조건화 경로와 후보 수를 고르고 자동 승격을 금지한다.
7. 5단계 이미지 쌍과 6단계 H3 후보가 통과해야 할 사람·자동 QA 기준을 함께 낸다.

### 출력

- `shot-cards.json`: shot, duration, camera, performance timeline, state pair, atomicity, H3 route
- state registry: start/end와 필요한 경우 서로 다른 mid guide
- `invariants`와 `allowed_change`
- semantic subject tracks와 tolerance: 저작·측정용이며 H3 직접 trajectory 입력은 아님
- plate candidate/acceptance 정책과 H3 best-of-N 정책
- semantic check, receipt, 입력 해시, 사람 gate

## 비교 실험

1–3단계는 해시로 고정하고 두 주제에 동일한 네 방식을 적용했다. 각 4단계 카나리아의 5단계 이미지에는 4단계 전체 shot 계약, 관련 2단계 시트, 1단계 방향과 요소 정의를 함께 전달했다.

| 방식 | 핵심 차이 | 실험 결과 |
|---|---|---|
| M1 prose baseline | 한 비트 한 샷, 산문, H3 I2V | 끝 상태가 없어 변화량을 검증할 수 없고 여러 행동이 한 이미지에 압축됨 |
| M2 state pair | 시작·끝·불변/허용 변화, FL2VA | 비교 가능해졌지만 원자 분해·다중 후보가 없어 시작부터 행동 중이고 쌍 드리프트 발생 |
| M3 atomic locked | 원자 샷, locked camera, semantic path | 구조는 개선됐으나 원본 문장 안 복합 동작은 `sub_beats` 없이는 실제로 분해되지 않음 |
| M4 H3 adaptive | M3 + H3 경로 선택, 다른 mid guide, best-of-N | 가장 완전한 기본 구조. 단일 5단계 샘플은 여전히 시작 상태·불변성 실패, 선발 게이트가 필수 |

비교 카나리아는 배관공 B07의 밸브 회전·연결부 작업과 펜트하우스 B02의 문턱 이동·손짓이었다. 후자는 한 문장 복합 동작인데 명시적 `sub_beats`가 없어 M3/M4도 안전하게 쪼개지 못했다.

사람 검수 뒤 프롬프트 hash를 대조하자 더 중요한 실험 한계가 드러났다. 배관공 A/C는 plate와 end 핵심 프롬프트가 같았고, 펜트하우스 A/C/D는 둘 다 같았다. M4가 후보 4개를 요청했지만 실제 5단계에서는 방식마다 한 장씩만 만들었으므로 best-of-N의 효과도 실행되지 않았다. 따라서 배관공 C가 상대적으로 안정적이었던 것은 M4의 우월성을 입증하지 않고 한 번의 생성 변동일 수 있다. 다음 비교는 원자화·좌표 방향·구체 lock·실제 후보 수를 각각 독립 변수로 실행해야 한다.

프롬프트 자체의 결함도 확인됐다. `object geometry`라는 일반 명사는 밸브 휠의 외경·허브·스포크 수나 공구가방 안 공구의 개수·색·배치를 고정하지 못했다. `거실 쪽으로`라는 장면 좌표 문장은 화면 좌표와 깊이 방향을 정하지 않으므로, 세 상태쌍 모두 호스트가 뒤로 걷는 것처럼 읽혔다.

전체 프레임 픽셀 변화량은 참고치일 뿐이다. 배관공의 평균 절대 변화량은 A/B/C/D 중 상태쌍이 있는 A/C/D가 각각 `0.0694 / 0.0477 / 0.0812`, 펜트하우스는 `0.0968 / 0.1524 / 0.0853`이었다. 이 수치는 요구 동작과 배경 드리프트를 구분하지 못하므로 합격 점수가 아니다. 실제 판정 순서는 `행동 전 시작 상태 → 요구 변화 완료 → 불변 요소 유지 → H3가 움직일 공간`이다.

## 구현에 반영한 규칙

- 정확 동작은 `locked` 카메라와 H3 state-pair 계열 경로를 사용한다.
- 3단계에 명시적 `sub_beats`가 있거나 문장 경계가 명확할 때만 자동 분할한다.
- 한 문장 복합 동작이 남으면 `manual-atomic-segmentation-required` 경고를 내고 5단계 전에 사람이 분할한다.
- 시작판 프롬프트는 접촉·이동·회전·도구 사용·제스처가 이미 시작된 모습을 명시적으로 금지한다.
- 시작판 후보 3개를 먼저 만들고 하나를 고른다.
- 정확 동작은 선택된 같은 시작판으로 끝판 편집 후보 3개를 만든다.
- 시작·끝을 독립 미관 선발하지 않고 한 쌍으로 평가한다.
- 관련 1단계 정의의 시각 필드를 `reference_locks`로 해시 결박하고, 밸브 외경·허브·스포크 및 공구가방 실루엣·내용물 개수·색·배치를 `geometry_locks`로 구체화한다.
- 이동 shot은 start plate에서 정규화 시작/끝 중심, 화면 방향 벡터, `toward_camera / away_from_camera / constant_depth`를 승인하기 전까지 end plate와 H3 생성을 차단한다.
- 바뀐 모든 픽셀 영역은 `allowed_change`, 접촉 그림자, 새로 드러난 배경 중 하나로 설명돼야 한다.
- 정확 동작 H3 후보는 최소 4개, 나머지는 최소 3개를 만들며 자동 승격하지 않는다.
- 중간 guide는 실제로 다른 관찰 상태일 때만 사용한다. 같은 still 반복은 정지와 펄스를 만들 수 있어 금지한다.
- 카메라 움직임과 정확한 큰 피사체 이동을 한 shot에서 동시에 요구하지 않는다. 필요하면 shot을 나누거나 피사체 제어 정확도를 비보장으로 표시한다.

## H3 영상 블라인드 결과

H3에서 두 주제별 7개, 총 14개 영상을 생성했다. 모두 768×1344, 24fps, 124프레임, 약 5.17초이며 2단계 시트를 H3 reference conditioning으로 전달했다. M2–M4는 방식별로 시드·프롬프트·첫 이미지·시트 순서를 고정하고 끝 이미지 유무만 바꿨다. M1은 애초 끝 상태가 없는 기준선이라 first-only만 만들었다.

### 펜트하우스

블라인드 키를 연 결과는 다음과 같다.

| 후보 | 조건 | 사람 판정 |
|---|---|---|
| A | M3 atomic locked, first-only | 1위. 팔을 내리고 돌아서 걸으며 카메라가 따라가는 흐름이 자연스러움 |
| F | M2 state pair, first-only | 2위. 회전·보행은 자연스럽지만 카메라가 따라가지 않고 마지막 재회전·팔 들기가 어색함 |
| G | M1 prose baseline, first-only | 전반적으로 나쁘지 않으나 실내 조명 깜빡임이 부적절함 |
| E | M4 H3 adaptive, first-only | 팔을 든 채 걷고 촬영 인력·조명 장비를 환각함 |
| B | M2 state pair, paired | 조금 걷고 다시 팔을 드는 동작이 어색함 |
| C | M3 atomic locked, paired | B와 같은 되돌림·재제스처 실패 |
| D | M4 H3 adaptive, paired | B와 같은 되돌림·재제스처 실패 |

M2와 M3에서는 first-only가 각각 2위와 1위였고 paired는 모두 실패했다. M4는 두 조건 모두 실패했지만 실패 형태가 달랐다. 끝 이미지는 호스트를 최종 정면 제스처로 되돌리려는 강한 제약으로 작동해 자연스러운 보행을 망쳤다. 따라서 복합 보행·회전·제스처 shot에서는 끝 이미지가 일관성을 높이기보다 잘못 설계된 최종 포즈로의 보간을 강제할 수 있다.

모든 실험 프롬프트는 locked camera를 요구했지만 사람은 호스트를 부드럽게 따라간 A를 가장 자연스럽다고 평가했다. 이는 카메라 고정이 항상 품질 목표가 아니라는 뜻이다. 정밀 접촉 shot에는 locked camera가 적합하지만, 인물 보행 shot은 `soft follow` 같은 의도적 카메라 정책을 자연어로 별도 허용해야 한다.

### 배관공

사람은 승자를 정하지 않았다. 핵심 원인은 끝 이미지보다 앞선 도구-대상 의미 실패였다. 1단계에는 빨간 도구가 파이프 렌치라고 정의돼 있었지만, 4단계의 작업 대상은 ID·화면 위치·형태 없이 `연결부`로만 기록됐고 `sublocation_id`도 unresolved였다. 밸브 돌리기, 렌치 꺼내기, 연결부 풀기, 살피기가 하나의 0–100% 구간에 묶였으며 시작·끝 상태도 물체 상태가 아니라 행동 문장을 반복했다.

| 후보 | 조건 | 대표 실패 |
|---|---|---|
| A | M2 state pair, paired | 핸들을 뽑고 빈 곳에 도구를 댐 |
| D | M2 state pair, first-only | 고정부까지 핸들과 함께 회전 |
| B | M3 atomic locked, first-only | 물 분출, 잘못된 도구와 접근 각도 |
| E | M3 atomic locked, paired | 핸들이 빠져 위로 이동 |
| F | M4 H3 adaptive, first-only | 상대적으로 논리적이나 접촉 각도와 팔 관통 실패 |
| G | M4 H3 adaptive, paired | 새 흰 기둥 출현과 잘못된 접촉 각도 |
| C | M1 prose baseline, first-only | 도구·마개 소실과 부자연스러운 후속 동작 |

모든 paired 후보에서 강한 형상 보간 오류가 보였지만 first-only도 도구 의미와 접촉 기하가 없어 실패했다. 따라서 배관공 결과만으로 앵커 효과의 우열을 확정할 수는 없고, 도구-대상 계약을 고친 뒤 재실험해야 한다.

### AI와 사람 판정 차이

사전 봉인된 AI 평가는 배관공에서 F를 1위로 두어 사람의 `그나마 논리적` 평가와 부분적으로 일치했지만, 팔 관통과 G의 새 기둥 같은 짧은 시간 오류를 과소평가했다. 펜트하우스에서는 AI가 G–F–A 순으로 평가했고 사람은 A–F 순으로 평가했다. AI는 정지 프레임의 배경 안정성을 더 높게 본 반면 사람은 카메라 추종, 팔을 내리는 시점, 다시 돌아서 제스처하는 부자연스러움을 더 중요하게 보았다. 시작·중간·끝 또는 균등 샘플 프레임만 보는 검수는 연속 동작의 개연성을 대체하지 못한다.

### H3 생성 음성의 처리

14개 영상의 H3 생성 음성은 사람 평가에서 제외했다. 말소리는 한국어가 아니었고 의미 있는 문장으로 들리지 않았으며 캐릭터의 입 움직임과도 맞지 않았다. 자동 QA의 `audio_present`는 단지 AAC 스트림의 존재만 확인했을 뿐 언어·내용·발화자·립싱크 품질을 보증하지 않는다.

H3가 만든 음성은 임시 생성 부산물로 취급한다. 영상 후보 비교와 화면 동작 승인에는 사용하지 않으며, 편집 입력으로 넘길 때 기본적으로 제거한다. 최종 한국어 내레이션·대사는 승인된 대본으로 별도 생성하고, 화면 속 인물이 실제로 발화해야 하는 shot만 별도의 립싱크 공정을 거친다. 비발화 shot에서는 입이 임의로 말하는 듯 움직이지 않는지도 영상 QA 항목으로 검사한다.

## 다음 검증

구체적인 후속 실험의 셀·시드·채택 기준은 `stage4-followup-experiment-design-2026-08-26.md`와 같은 이름의 JSON 실행 명세에 고정했다.

- 도구에 `target_part_id`, 접촉면, 접근 각도, 힘의 결과, 고정 반작용 부품을 명시한다.
- 5단계 시작판에서 실제 렌치가 물 수 있는 이음부가 가려지지 않고 읽히는지 gate한다.
- 밸브 잠그기와 연결부 풀기를 서로 다른 원자 shot으로 분리한다.
- 배관공 수정본에서 first-only 대 paired를 다시 비교한다.
- 보행 shot은 `locked`와 `soft follow` 카메라 프롬프트를 독립 변수로 비교한다.
- 사람 검수에는 전 구간 재생을 강제하고, AI 검수에는 접촉·관통·일시적 객체 출현·조명 깜빡임을 위한 고밀도 시간축 검사를 추가한다.
- H3 원본 음성은 기본 폐기하고 별도 한국어 음성 제작과 선택적 립싱크를 후속 공정으로 분리한다.
