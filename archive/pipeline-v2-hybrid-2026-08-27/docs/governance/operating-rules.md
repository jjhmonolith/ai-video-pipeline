# 계약·승인·산출물 운영 규정

> 적용 범위: 이 저장소의 현행 파이프라인과 진행 중인 제작 런  
> 기준일: 2026-08-25

## 1. 계약의 종류

### Attempt 제작 계약

`<attempt>/01-premise/output/contract.json`이 한 시도의 실행 조건을 정한다. 단계 역할, 생성 프레임, 납품 프레임, 이미지 역할, 시트 정책, 프롬프트 조항, 요소, 조사 상한, 시나리오 구조를 도구가 직접 읽는다.

- 계약을 바꾸면 새 digest가 생긴다.
- 이전 digest로 만들어진 산출물은 자동으로 새 계약을 충족한 것으로 간주하지 않는다.
- 프레임·금지 문구·단계 경로를 도구 상수로 복사하지 않는다.
- 계약 수정 후 영향을 받는 하류 단계를 다시 검사한다.
- 조항이 없는 단계의 영수증도 계약 digest 검사를 생략하지 않는다.
- 전체 digest가 달라도 해당 단계의 입력 hash·조항·실행 계획이 같고 사람이 호환성을 확인한 경우, 원래 영수증을 고치지 않고 단계 `qa/contract-compatibility.json`에 범위·근거·승인자를 기록한다.

### 생성 프레임과 납품 프레임

- `frame`은 `05-plate`와 `06-motion`이 사용하는 생성 네이티브 래스터다.
- `delivery_frame`은 `07-edit`가 내보내는 최종 래스터다. 플랫폼 업로드 권장값을 생성 요청에 넣지 않는다.
- 로컬 `minimax-h3-local-768p` 프로파일은 가로 `1344×768` 또는 세로 `768×1344`, `24fps`만 허용한다.
- 생성 프레임과 납품 프레임이 다르면 `delivery_frame.transform`에 크롭, 스케일, 근거를 명시한다. 기록되지 않은 확대·리타이밍은 금지한다.
- 계약 검증기와 H3 런타임이 모두 프로파일을 검사한다. 문서 기본값만으로 안전하다고 간주하지 않는다.

### 실행 모드와 Human gate 계약

`contracts/human-gates.v1.json`은 사람이 판단해야 하는 지점을 정의한다. 자동 검사는 후보와 증거를 정리할 수 있지만 승인자를 대신하지 않는다.

- `<attempt>/qa/execution-mode.json`이 없으면 `normal`이다. Normal에서는 `form_ok`와 사람 승인 완료를 구분하고 모든 기존 human gate를 유지한다.
- `fast_track`은 사용자가 해당 attempt에 명시적으로 지시했을 때만 기록할 수 있다. 이전 attempt나 일반적인 "계속" 지시에서 추론하지 않는다.
- Fast-track에서는 AI가 내부 gate와 review packet을 `ai_fast_track`으로 판정·적용하고 다음 단계로 즉시 진행한다. 판정 기준, 시각 증거, reviewer, accepted defect를 영수증에 남긴다.
- Fast-track 10회차의 비안전 품질 실패는 `accepted_defect`로 기록해 진행할 수 있다. 권리·안전·새 권한·상호 모순 계약은 이 규칙으로 우회하지 않는다.
- 모드 변경 뒤 작성된 manifest만 유효하다. 모드 영수증과 manifest의 mode·set_at이 다르면 새 manifest를 준비한다.
- 외부 공개·배포·메시지·구매는 두 모드 모두 별도 권한이 필요하다. Fast-track의 G10 내부 판정은 외부 release authority가 아니다.

### 참고 계약

`contracts/reference/`의 문서는 `design-only` 참고 자료다. 아직 현행 런타임을 구속하지 않으며, 구현할 때 현행 8단계 계약과 다시 조정해야 한다.

## 2. 산출물과 증거

- 프롬프트 원문과 외부 호출 파라미터를 남긴다.
- 영수증에는 입력·결과 경로, 모델, 시간, 계약 digest를 남긴다.
- 생성 공급자와 실행 표면을 구분한다. Codex 앱·CLI 직접 생성은 `generator.mode: codex`와 실제 `surface`를 남기며 노출되지 않은 토큰 수치를 추정하지 않는다.
- Codex 모드는 API 키를 읽거나 API 모드로 자동 대체하지 않는다. 대량·무인 실행은 별도 승인된 API 작업으로 취급한다.
- Codex 앱·CLI의 정식 시트는 방향에 따라 관측된 네이티브 래스터 `1672×941` 또는 `941×1672`와 `high`로 요청한다. `high` 표기만으로 픽셀 크기를 충족했다고 보지 않는다.
- 시트 후보가 허용오차보다 작으면 후보 증거로 남기고 같은 작업의 다음 변주 시도를 생성한다. 작은 원본을 확대해 채택본으로 기록하지 않으며, 최대 10회 전체 실패 때만 마지막 후보와 결함을 검토 단계로 넘긴다.
- 판은 시트 규격을 상속하지 않는다. 영상 `frame`과 유사한 공급자 크기를 요청하고 정확한 `frame`으로 축소한다.
- 채택본과 폐기본을 분리한다.
- 자동 QA 결과를 사람 승인으로 표현하지 않는다.
- 조사 사진은 근거 자료다. 권리·상표·실존 인물 문제가 있으므로 생성 입력으로 자동 승격하지 않는다.

## 3. 생성·표기 원칙

- 읽혀야 하는 문자·숫자·라벨·지도는 결정론적 편집 레이어가 만든다.
- 실제 인물 likeness를 생성하지 않는다.
- 익명 재현을 쓸 때는 실제 기록물로 오인되지 않도록 결과물에 재현 고지를 둔다.
- 브랜드·저작권·초상·문화적 위험은 자동 검사만으로 닫지 않고 해당 human gate로 보낸다.

이 항목은 법률 자문을 대신하지 않는다. 실제 공개 전에는 사용 지역·채널·소재에 맞는 권리 검토가 별도로 필요하다.

## 4. 보존과 아카이브

- 진행 중인 현행 attempt만 `runs/`에 둔다.
- 끝났거나 구조가 폐기된 attempt는 폴더 전체를 `archive/runs/`로 옮긴다.
- 아카이브 안의 단계명과 내부 구조는 당시 상태 그대로 유지한다.
- `.DS_Store`, Python bytecode, 테스트 캐시는 삭제한다.
- 실행 로그가 재현·실패 분석의 유일한 근거라면 해당 단계 `qa/`에 보존한다. 단순 중복 콘솔 로그는 영수증에 정보가 있음을 확인한 뒤 제거할 수 있다.
- 루트 `renders/`의 임시물은 source of truth가 아니다.

## 5. 문서 상태

- `docs/`는 현행 규약과 다음 구현에 필요한 문서만 둔다.
- `research/`와 `docs/research/`는 근거이며 아직 규약이 아니다.
- `archive/docs/`는 과거 설계다. 아이디어를 참고할 수 있지만 현행 단계 이름을 결정하지 않는다.
- 규약 변경은 코드·테스트·문서를 함께 갱신한다.
